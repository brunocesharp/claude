# Contexto do Projeto — Marketplace de Skills para Claude Code

## Objetivo Geral

Criar um **marketplace de plugins** para o Claude Code que cobre o ciclo completo de desenvolvimento de software — do discovery ao deploy. Cada plugin agrupa skills relacionadas e é instalado via `/plugin marketplace add` + `/plugin install`.

---

## Visão do Ciclo Completo

| Fase | Objetivo | Status |
|---|---|---|
| **Discovery** | Construção da ideia e contexto do projeto | ✅ Implementado |
| **Escopo** | Consolidação do discovery em documento formal | ✅ Implementado |
| **Especificação** | Detalhamento das regras de negócio via BDD | ✅ Implementado |
| **Plano de Execução** | Decomposição técnica fullstack com estimativas | ✅ Implementado |
| **Arquitetura .NET** | Geração de código Clean Architecture + DDD + CQRS | ✅ Implementado |
| **Arquitetura Angular** | Geração de código por camada (Core / Feature / Shared) | ✅ Implementado |
| **Deploy** | Pipeline de build, testes e publicação | ✅ Implementado |
| **Documentação de Negócio** | Análise de código e geração de docs de regras | ✅ Implementado |
| **Especificação Não-Funcional** | Requisitos de desempenho, segurança, escalabilidade | ⬜ Não implementado |
| **Refinamento de Telas** | Especificação de UI/UX e fluxos de navegação | ⬜ Não implementado |

---

## Decisões de Design

- **Skills modulares** — uma skill por documento ou responsabilidade, em vez de uma skill end-to-end.
- **Interação conversacional + geração de documentos** — Claude conduz perguntas por blocos temáticos e ao final gera os arquivos `.md` ou código.
- **Organização em plugins** — skills agrupadas por fase/stack em `plugins/<plugin>/skills/<nome-da-skill>/SKILL.md`.
- **Público-alvo** — múltiplos perfis: Product Manager, Tech Lead, Desenvolvedor, Analista de Sistemas.
- **Armazenamento de docs** — documentos gerados ficam em `docs/` dentro do projeto real.
- **Armazenamento de código** — skills de arquitetura geram código diretamente no projeto.

## Plugins e Skills Implementadas

### Plugin: `discovery`

#### 1. `discovery-init`
**Gatilho:** "iniciar projeto", "novo projeto", "começar discovery", "criar projeto"
- Coleta nome, descrição, URL do repositório e tipo de projeto
- Gera `docs/project.md` com metadados e status das fases
- Ponto de entrada obrigatório para todas as outras skills de discovery

#### 2. `discovery-vision`
**Gatilho:** "visão do projeto", "definir visão", "proposta de valor", "público-alvo"
- Conduz conversa em blocos: Problema → Público-Alvo → Proposta de Valor → Restrições
- Gera `docs/discovery/vision.md`

#### 3. `discovery-opportunity`
**Gatilho:** "oportunidades do projeto", "mapear dores", "jobs to be done"
- Frameworks: Opportunity Solution Tree (Teresa Torres) + Jobs to Be Done
- Foco total no problema — nunca sugere soluções durante a execução
- Gera `docs/discovery/opportunity.md`

#### 4. `discovery-assumptions`
**Gatilho:** "hipóteses do projeto", "premissas", "o que ainda não sabemos"
- Frameworks: Assumption Mapping (Bland & Osterwalder) + Lean Startup
- Matriz de priorização: alto impacto + baixa certeza = validar primeiro
- Gera `docs/discovery/assumptions.md`

#### 5. `discovery-stakeholders`
**Gatilho:** "stakeholders", "partes interessadas", "quem aprova", "mapa de envolvidos"
- Matriz poder/interesse para classificar stakeholders
- Inclui matriz de comunicação com canal, frequência e responsável
- Gera `docs/discovery/stakeholders.md`

#### 6. `discovery-metrics`
**Gatilho:** "métricas do projeto", "como medir sucesso", "KPIs", "OKRs"
- Frameworks: OKR, North Star Metric, HEART (Google)
- Converte métricas vagas em métricas mensuráveis com baseline e meta
- Gera `docs/discovery/success-metrics.md`

#### 7. `scope-generate`
**Gatilho:** "gerar escopo", "criar escopo", "montar escopo", "escopo do módulo"
- Lê todos os arquivos de `discovery/` e escopos existentes
- Evita repetição de funcionalidades em escopos `Aprovado` ou `Em execução`
- Cria pasta `docs/escopo/{titulo}/` com `escopo.md` e cópias dos docs de discovery
- Estados: `Rascunho → Em revisão → Aprovado → Em execução → Concluído`

### Plugin: `spec-plan`

#### 8. `spec-functional`
**Gatilho:** "especificação funcional", "regras de negócio", "critérios de aceitação", "cenários BDD"
- Metodologia BDD com Feature Injection (In order to / As / I want)
- Conduz extração de cenários Given/When/Then por feature
- Suporta Esquema do Cenário com tabelas para múltiplas combinações
- Depende de: `scope-generate`
- Gera `docs/especificacao/{escopo}/spec-functional.md`

#### 9. `dotnet-execution-plan`
**Gatilho:** "plano de execução", "planejar implementação", "dividir em tarefas", "execution plan"
- Gera plano fullstack (.NET + Angular) com entregas incrementais
- Decompõe tarefas por camada com estimativas (Domain → Infra → Application → Presentation → Angular)
- Cada entrega deve ser deployável de forma independente
- Guia de decisão BehaviorSubject vs NgRx incluído
- Gera `execution-plan.md`

---

### Plugin: `architecture-dotnet`

#### 10. `dotnet-clean-architecture`
**Gatilho:** "clean architecture", "estrutura de projeto .NET", "camadas .NET", "criar projeto .NET estruturado"
- Define a estrutura de camadas: Domain / Application / Infrastructure / Presentation
- Documenta responsabilidades, regras de dependência e convenções de nomenclatura
- Referências por camada em `References/`

#### 11. `dotnet-domain-entity`
**Gatilho:** "criar entidade", "entity", "aggregate root", "value object", "modelo de domínio"
- Gera Entity, Aggregate Root, Value Object, Enum de domínio e interface de repositório
- Padrão: construtor privado + factory method `Create()` + setters `private`
- Sem dependências de infraestrutura (EF, Dapper etc.)

#### 12. `dotnet-application-feature`
**Gatilho:** "criar command", "criar query", "caso de uso", "handler", "CQRS"
- Gera Command + CommandHandler + Validator (FluentValidation)
- Gera Query + QueryHandler + DTO
- Retorno obrigatório com `Result<T>` (Result Pattern)
- Injeção apenas de interfaces — nunca implementações

#### 13. `dotnet-infrastructure-repository`
**Gatilho:** "criar repositório", "repository", "implementar repositório", "persistência"
- Gera implementação herdando de `RepositoryBase<TEntity, TId>`
- `CancellationToken` propagado; `AsNoTracking()` onde apropriado
- Registra no DI em `Infrastructure/DependencyInjection.cs`

#### 14. `dotnet-external-service`
**Gatilho:** "integração com API", "API externa", "chamar API", "adapter", "gateway", "HTTP client"
- Padrão Adapter/Gateway herdando de `HttpClientBase`
- Resiliência com Polly: retry, circuit breaker, timeout
- OAuth2/Bearer Token via settings; logging estruturado sem dados sensíveis
- Retorna `Result<T>` em todos os métodos

#### 15. `dotnet-endpoint-generator`
**Gatilho:** "criar endpoint", "controller", "minimal API", "rota", "HTTP GET/POST/PUT/DELETE"
- Gera Controller (MVC) ou Minimal API com OpenAPI (`ProducesResponseType`)
- Integra via MediatR usando `ISender` (não `IMediator`)
- Trata respostas via Result Pattern

#### 16. `dotnet-deploy-homolog`
**Gatilho:** "deploy homologação", "deploy homolog", "publicar em homologação", "deploy staging"
- Pipeline sequencial: Restore → Build → Test → Docker Build → Deploy → Health Check
- Interrompe imediatamente em qualquer falha
- Gera relatório de sucesso ou falha com artefatos e ação sugerida

#### 17. `dotnet-deploy-prod`
**Gatilho:** "deploy produção", "deploy prod", "publicar em produção", "go live"
- Confirmação obrigatória do usuário antes de iniciar
- Validação prévia: branch `main/master`, sem commits pendentes, variáveis de ambiente configuradas
- Pipeline idêntico ao homolog com etapa extra de validação e rollback documentado
- Inclui procedimento de rollback com `docker tag + docker compose`

---

### Plugin: `architecture-angular`

#### 18. `angular-core-layer`
**Gatilho:** "camada core Angular", "core service", "SignalR Angular", "interceptor Angular", "guard Angular"
- Gera: Core Service, Core Hub (SignalR), HTTP Service, Interceptor, Guard, Resolver, Model/Interface, Error Handler
- `providedIn: 'root'` para todos; injeção via `inject()` (Angular 17+)
- `takeUntilDestroyed` obrigatório em subscriptions

#### 19. `angular-feature-layer`
**Gatilho:** "criar feature Angular", "smart component", "NgRx feature", "reactive form", "lazy load Angular"
- Gera: Smart/Dumb Components, Pages, Store NgRx (Actions/Reducers/Effects/Selectors), Forms, Feature Services, Routing
- Standalone components com `ChangeDetectionStrategy.OnPush`
- `createFeature()` do NgRx; Reactive Forms com `nonNullable`

#### 20. `angular-shared-layer`
**Gatilho:** "shared component", "componente compartilhado", "pipe Angular", "directive Angular", "UI library"
- Gera: Dumb Components reutilizáveis, Pipes customizados, Directives de comportamento, configuração de UI Library
- Princípio: sem lógica de negócio, sem acesso à Store, funciona em qualquer contexto
- Suporte a Angular Material, PrimeNG e Tailwind

#### 21. `angular-rxjs-transversal`
**Gatilho:** "RxJS", "Observable", "BehaviorSubject", "operadores RxJS", "switchMap", "combineLatest", "memory leak Angular"
- Guia completo de operadores e padrões RxJS por camada Angular
- Fluxo de decisão: qual operador usar para cada cenário
- Regras de ouro: `takeUntilDestroyed`, `async pipe`, `toSignal`, `shareReplay(1)`
- Referências: criação, operadores, combinação, erros, subscriptions, padrões, interop com Signals

---

### Plugin: `business-docs`

#### 22. `business-docs`
**Gatilho:** "documentar regras de negócio", "gerar docs de negócio", "documentar domínio", "business docs"
- Analisa código implementado (.NET Domain/Application + Angular services/guards/store)
- Cria tasks atômicas por área (< 1 hora cada)
- Numeração sequencial global de regras (RN-XXX)
- Cita arquivo e linha de cada regra; não duplica regras existentes
- Gera `docs/business/{area}.md`
